# 핑키토랑 마커 기록(record) JSON 형식

Pinky Pro (ROS 2 Jazzy), AprilTag 36h11 정밀 정렬·도킹에서 쓰는 기록 파일의 형식과 좌표 규칙을 정리한 문서입니다.
기록 파일은 "그 자리에서 마커가 이렇게 보였다 = 정답 자세"를 저장하고, 주행할 때 이 값과 비교해서 자세를 맞춥니다.

- 위치: 레포 `src/fleet_agent/records/` (모든 로봇 공통, 카메라 보정만 `records/cam/<hostname>.json`). 읽기 · 쓰기는 `docking/records.py`.
  예전처럼 `~/`에만 있는 파일도 읽음 (레포에 없을 때). 아래 문서의 `~/파일` 표기는 파일 이름으로 보면 됨
- 만드는 프로그램: `ros2 run fleet_agent dock_record` (레포 `src/fleet_agent/fleet_agent/docking/dock_record.py`)
- 쓰는 곳: `docking/corridor.py` (N14 정렬, 통로 후진, 도크 들어가기), `docking/undock.py` (빠지기)
- 단위: 거리 m, 각도 rad, 초점거리 px

---

## 0. 공통 좌표 규칙

**로봇 좌표**
- X는 앞, Y는 왼쪽, 각도는 반시계(왼쪽)가 +입니다.
- 카메라는 로봇 앞쪽에 있고, 로봇 중심(base_footprint)에서 앞으로 `CAM_X = 0.035 m` 떨어져 있습니다.

**카메라 측정값** (`marker_dock.measure_corners`, solvePnP IPPE_SQUARE)

| 값 | 뜻 |
|---|---|
| `tz` | 카메라에서 마커까지 앞쪽 거리 (m) |
| `tx` | 마커가 화면 오른쪽에 있으면 + (m) |
| `yaw` | 로봇이 벽과 수직이 되려면 돌아야 하는 각 (+ = 왼쪽) |

`yaw`는 마커 사다리꼴 모양(좌우 세로변 길이 차)으로 구합니다.

**로봇 좌표에서 본 마커 위치**
```
M = (CAM_X + tz, -tx)
```

**방위각 bearing** (로봇 중심에서 본 마커 방향, + = 왼쪽)
```
bearing = atan2(-tx, CAM_X + tz)
```
- 멀어도 안정적입니다. 50 cm에서도 0.1° 수준입니다.

**기울기 yaw는 가까울 때만 믿음**
- 2.5 cm 마커는 약 22 cm 안, 5 cm 마커는 약 44 cm 안에서만 믿습니다 (마커 크기에 비례).
- 그보다 멀면 1 px 차이가 몇 °씩 납니다.

**측정 방식**
- 로봇이 멈춘 상태에서 여러 장(8~30장)을 찍어 중앙값을 씁니다.
- 움직임은 odom(TF `odom -> base_footprint`)으로 합니다.

## 1. 정렬 기록: `align_<이름>.json`

그 자리, 그 방향에서 마커가 어떻게 보였는지를 그대로 저장합니다.

```json
{
  "id": 5,
  "size": 0.05,
  "bearing": 0.0017,
  "tz": 0.513,
  "yaw": -0.0087
}
```

| 키 | 뜻 | 단위 |
|---|---|---|
| `id` | 마커 ID | - |
| `size` | 마커 검은 사각형 한 변 | m |
| `bearing` | 로봇 중심에서 본 마커 방향 (+ 왼쪽) | rad |
| `tz` | 카메라 -> 마커 앞쪽 거리 | m |
| `yaw` | 벽과 수직이 되려면 돌 각 (+ 왼쪽). 가까울 때만 정확 | rad |

**주행할 때 쓰는 법**
- **방향 맞추기**
  - 마커가 가까우면 `yaw - 기록 yaw`만큼 제자리에서 돕니다.
  - 마커가 멀면 `bearing - 기록 bearing`만큼 돕니다.
- **거리 맞추기:** `tz - 기록 tz`만큼 지금 방향 그대로 앞이나 뒤로 갑니다. 양수면 앞으로 갑니다.

**파일 목록** (지도: 북쪽 위)

| 파일 | 로봇 자리 | 앞이 보는 쪽 · 마커 | 쓰는 곳 |
|---|---|---|---|
| `align_n14e.json` | N14 (빨간 원) | 동쪽 벽 · 마커 4 (5 cm) | N13에서 와서 N14 동서 위치·방향 |
| `align_n14s.json` | N14 | 남쪽 벽 · 마커 5 (5 cm) | 우로 90° 돈 뒤 후진 축 (벽과 수직) |
| `align_n15s.json` | N15 (D3 칸 정면) | 남쪽 벽 · 마커 5 (약 51 cm) | D3 들어가기 전 N15 앞뒤 위치, D3 빠지기 끝 정렬 |

통로 후진 방향은 이 기록이 아니라 라이다로 잰 양옆 벽과 평행하게 잡습니다. 마커 5 벽이 통로와 약 3.8° 틀어져 있기 때문입니다. 그래서 P2 기록(`align_p2s`)은 더 이상 쓰지 않습니다.

## 2. 도킹·자리 기록: `dock_target_<이름>.json`

마커를 원점으로 하는 "도크 좌표계"에서 로봇 자세를 저장합니다.

```json
{
  "gx": 0.376,
  "gy": -0.014,
  "gth": -3.136,
  "fx": 513.2,
  "size": 0.025
}
```

| 키 | 뜻 | 단위 |
|---|---|---|
| `gx` | 벽(마커)에서 로봇 중심까지 법선 방향 거리 | m |
| `gy` | 마커 정면선에서 옆으로 벗어난 거리 (도크 좌표 y) | m |
| `gth` | 도크 좌표계에서 로봇 방향. ±π(±180°)이면 벽을 정면으로 봄 | rad |
| `fx` | 기록할 때 쓴 카메라 초점거리 (`dock_cam.json` 값) | px |
| `size` | 마커 한 변 | m |

**도크 좌표계**
- 원점은 마커입니다.
- x축은 벽의 법선으로, 벽에서 로봇 쪽(칸 안쪽)을 향합니다.
- y축은 x축에서 왼쪽으로 90° 돌린 방향입니다.

**계산** (레포 `marker_dock.py`)
```python
# 기록할 때: 측정값 m -> (gx, gy, gth)
D, phi = dock_in_odom(m, (0, 0, 0))          # 로봇을 원점으로 둔 마커 위치 D, 벽 법선 각 phi
rel = rot(-phi) @ (0 - D)
gx, gy, gth = rel[0], rel[1], wrap(0 - phi)

# 주행할 때: 지금 잰 마커(D, phi, odom 좌표) -> 목표 odom 자세
x, y = D + rot(phi) @ [gx, gy]
th   = wrap(phi + gth)
```

**파일 목록**

| 파일 | 로봇 자리 | 마커 | 쓰는 곳 |
|---|---|---|---|
| `dock_target_n15.json` | N15, 서쪽(마커 3)을 정면으로, 마커 약 15 cm | 3 (2.5 cm) | D3 빠지기(undock)의 나올 자리, 들어가기 전 N15 맞추기 |
| `dock_target_d3.json` | D3 칸 안 최종 주차 자세 | 3 (2.5 cm) | 후면 주차 정답 |

`dock_target_d3.json`은 도크 안(마커 약 34 cm)에서 재지 않습니다. 그 거리에서는 기울기가 몇 °씩 틀리기 때문입니다. 대신 이렇게 만듭니다.
1. D3에 반듯하게 넣은 로봇을 앞으로 곧게 빼서 N15에서 잽니다. 마커가 15 cm라 정확합니다.
2. 그 값에서 odom으로 잰 "나온 거리" `s_out`만큼 같은 방향으로 뒤로 옮긴 값을 d3로 저장합니다.

```python
d3 = dict(n15)
d3['gx'] = n15['gx'] - s_out * cos(n15['gth'])
d3['gy'] = n15['gy'] - s_out * sin(n15['gth'])
```

그래서 `n15`와 `d3`는 같은 줄 위에 있습니다. `gy` 차이 0, `gth` 차이 0이면 정상입니다.

## 3. 카메라 보정: `dock_cam.json`

```json
{ "fx": 513.2 }
```

- `ros2 run fleet_agent marker_dock --calibrate`로 한 번 만듭니다.
- 마커 정면 25~35 cm에서 odom으로 10 cm 움직이고 거리 변화를 비교해 구합니다.
- 영상 크기는 640x480이고 cx, cy는 영상 중심입니다. 왜곡 보정은 없습니다.
- 모든 측정이 이 `fx`를 씁니다. `fx`가 바뀌면 기록을 다시 해야 합니다.

## 4. 만드는 명령 (로봇에서, bringup + 바닥 센서 켜고, fleet_agent는 끈 상태)

```bash
# 손으로 놓는 건 D3 하나. 나머지는 로봇이 직접 벽과 수직으로 맞추고 찍음
ros2 run fleet_agent dock_record all
# 순서: D3(손) -> 곧게 나와 N15: n15, d3 -> 좌90(남): n15s
#       -> 축 그대로 전진해 N14: 남쪽 벽 수직, n14s -> 좌90(동): 동쪽 벽 수직, n14e

ros2 run fleet_agent dock_record dock --dock d2            # 도크 쪽만 (d2 · n16 · n16s)
ros2 run fleet_agent dock_record align <이름> --id <마커ID>  # 그 자리에서 정렬 기록 하나 (기본 5 cm)
ros2 run fleet_agent dock_record check                     # rad -> cm · ° 로 출력, n15와 d3 차이도 확인
ros2 run fleet_agent dock_record scan                      # 지금 자리에서 라이다로 양옆 벽이 보이나
```

`all`(N15) · `dock --dock d2`(N16)가 끝난 자세(좌90, 남쪽을 봄)에서 바닥 센서 3개 바로 밑에 그 노드의 가로선을 붙입니다.
통로 docking은 이 선을 밟는 순간을 그 노드 도착으로 칩니다 (`docking/corridor.py` BAR_*).

## 5. 마커 ID (최종 맵)

| ID | 크기 | 위치 |
|---|---|---|
| 1 | 2.5 cm | D1 왼쪽 바깥 벽 |
| 2 | 2.5 cm | D2 맞은편 칸막이 (N16 옆) |
| 3 | 2.5 cm | D3 맞은편 칸막이 (N15 옆) |
| 4 | 5 cm | N14 동쪽 벽 |
| 5 | 5 cm | N14 남쪽 벽 |
| 6 | 5 cm | 입구 박스 아랫면 (D1 정렬) |
| 11·12 ~ 61·62 | - | 테이블 다리 (테이블 번호 + 1 왼쪽 / 2 오른쪽) |

도크 이름은 최종 맵 기준입니다 (D1, 오른쪽 위 D2, 아래 D3). `node_graph.yaml` v7.1 · `precision_stops.yaml`도 같은 이름입니다.
